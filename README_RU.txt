MEMBER ONLINE — стартовый проект для Netlify + Render
=====================================================

Что в ZIP
- public/ — фронтенд сайта (HTML/CSS/JavaScript), который публикуется на Netlify.
- server/index.js — API и WebSocket для реальных аккаунтов и личных сообщений.
- package.json — зависимости Node.js.
- render.yaml — шаблон деплоя API на Render.
- netlify.toml — настройки публикации статического сайта.

Что уже реализовано в коде
- Регистрация и вход по username + паролю (пароли хранятся в виде bcrypt-хеша).
- JWT-сессия.
- Профиль и анонимный номер Member ID.
- Поиск пользователей по имени, username и Member ID.
- Личные сообщения через API + Socket.IO в реальном времени.
- Демонстрационный каталог коллекционных подарков и отправка подарка.
- Демонстрационный маркет username с выставлением лотов.
- JSON-хранилище на диске Render Persistent Disk (путь /var/data/member-data.json).

Ограничения — прочитай перед публичным запуском
Это ранняя версия для разработки, а не production-ready сервис. Нужны тестирование, лимиты запросов, защита от спама, подтверждение почты/восстановление пароля, блокировки и жалобы, проверка прав доступа, резервные копии и политика конфиденциальности.
- Группы/каналы, отправка реальных файлов, push-уведомления и звонки пока не реализованы.
- Подарки сейчас — внутренние коллекционные записи, НЕ настоящие on-chain NFT. Реальные NFT требуют выбора блокчейна, смарт-контракта, кошелька, оплаты комиссий и аудита.
- Username-маркет пока демонстрационный. Покупка намеренно отключена; нет оплаты, escrow или реальной передачи username.
- Анонимный номер — внутренний ID, а не телефон и не гарантия полной анонимности.
- JSON-файл годится для раннего прототипа с малой нагрузкой, но не для масштабного сервиса. Для роста лучше PostgreSQL/Supabase.
- В render.yaml указан бесплатный план, если он доступен в твоём аккаунте. У бесплатных инстансов могут быть ограничения/засыпание. Persistent Disk может требовать платный тариф Render — проверь текущие условия в панели Render.
- JWT_SECRET должен быть секретным. Не публикуй его в коде.
- CLIENT_ORIGIN="*" упрощает первый запуск, но для production замени на точный домен Netlify.

КАК ЗАПУСТИТЬ (без программирования по возможности)
A. Загрузить backend на Render
1. Создай репозиторий на GitHub и загрузи в него содержимое этой папки. Render обычно разворачивает проект из GitHub.
2. В Render выбери New > Blueprint и подключи репозиторий с render.yaml, либо создай Web Service вручную.
3. Build Command: npm install
   Start Command: npm start
4. Убедись, что переменные окружения настроены:
   NODE_ENV=production
   JWT_SECRET=<случайный длинный секрет>
   DB_FILE=/var/data/member-data.json
   CLIENT_ORIGIN=*
5. Если включаешь Persistent Disk, mount path должен быть /var/data. Сохрани URL backend, например https://member-messenger-api.onrender.com.
6. Проверь URL/ api/health — должен вернуться JSON с ok:true.

B. Подключить сайт Netlify
1. В Netlify импортируй тот же GitHub-репозиторий.
2. Base directory оставь пустым; Publish directory укажи public. Команда сборки не нужна.
3. После публикации скопируй домен сайта Netlify.
4. В файле public/config.js замени пустую строку на URL backend:
   window.MEMBER_API_URL = "https://ТВОЙ-API.onrender.com";
5. Сохрани изменения и отправь их в GitHub. Netlify пересоберёт сайт.
6. В Render переменную CLIENT_ORIGIN лучше заменить на точный URL Netlify, затем перезапустить backend.

C. Проверка
1. Открой сайт Netlify.
2. Создай аккаунт с username из латиницы/цифр/подчёркивания (3–24 символа), именем и паролем минимум 8 символов.
3. Открой сайт в другом браузере/инкогнито и создай второй тестовый аккаунт.
4. Найди второго пользователя по username, начни чат и отправь сообщение.
5. Не используй реальные пароли, которые используешь в других сервисах, пока это ранняя версия.

Локальный запуск (если есть компьютер)
- Установить Node.js 20+
- В корне проекта: npm install
- Задать JWT_SECRET и запустить: npm start
- Открыть public/index.html через локальный веб-сервер; для API указать http://localhost:10000 в public/config.js.
